# backend — 水たまりゼロ東京

Python + FastAPI。東京都の地形データから水たまりのできやすい地点を割り出し、
歩行空間ネットワーク上で「最短ルート」と「水たまり回避ルート」を返す。

## セットアップ

```bash
cd backend
uv venv --python 3.12 .venv          # または python3.12 -m venv .venv
uv pip install --python .venv/bin/python -e ".[dev]"
```

## 起動

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
```

`data/generated/` はリポジトリに入れてあるので、そのまま起動できる。
元データから作り直したいときだけ次を実行する（ネットワークが必要）。

```bash
.venv/bin/python scripts/build_data.py            # キャッシュがあれば再利用
.venv/bin/python scripts/build_data.py --refresh  # 標高タイル・OSMを取り直す
```

## テスト

```bash
.venv/bin/python -m pytest tests -q
```

## エンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/health` | 起動確認。読み込み済みの危険地点数を返す |
| GET | `/api/area` | デモ対象地域の範囲と、雨量セレクタの選択肢 |
| GET | `/api/place` | 地図上の1点に付ける呼び名（`?lat=&lng=`） |
| POST | `/api/route` | 最短ルート・回避ルート・危険地点をまとめて返す |

`POST /api/route` のリクエスト:

```json
{
  "origin": { "lat": 35.6812, "lng": 139.7671 },
  "destination": { "lat": 35.6751, "lng": 139.7628 },
  "intensity": "medium"
}
```

`intensity` は `light` / `medium` / `heavy`。
レスポンスはフロントの `SearchResult` 型（`frontend/src/types.ts`）と1対1で対応している。
`app/models.py` を変えるときは、必ず `types.ts` もそろえて変えること。

エラーは `{"detail": "..."}` の形で返す。日本語の文面をそのまま画面に出せるようにしてある。

- 400 … 対象地域の外、出発地と目的地が近すぎる、経路が見つからない、
  指定地点から歩ける道が遠すぎる（120m超）
- 422 … `intensity` が不正など、スキーマ違反
- 503 … 生成済みデータが無い（`scripts/build_data.py` の未実行）

対話的なAPIドキュメントは起動後 http://localhost:8000/docs で見られる。

## デモ対象地域

東京駅〜有楽町駅〜日比谷〜京橋（`35.6700,139.7570` 〜 `35.6870,139.7760`）。
`app/config.py` の `DEMO_AREA` を書き換えて `build_data.py` を回せば別の範囲にできる。

| データ | 出典 | 用途 |
| --- | --- | --- |
| 標高タイル DEM5A（5mメッシュ） | 国土地理院 | 窪地・傾斜・流域の計算 |

## 水たまり予測の考え方

`scripts/build_data.py` が次の順に処理する。

1. **標高グリッドを作る**（`app/terrain.py`）
   国土地理院のDEM5Aタイルをデモ対象地域ぶん取得してモザイクにする。
   1セルおよそ 3.9m、488×443 のグリッドになる。

2. **地形指標を出す**（`app/terrain.py`）
   - **窪地の深さ** — priority-flood 法で窪地を埋め、埋める前との差を取る。
     これがそこに溜まりうる水深にあたる。
   - **流域面積** — 微小な傾きを付けて埋めた標高の上で D8 の流向をたどり、
     どれだけの範囲の雨水がそのセルへ集まるかを積み上げる。
     平坦面で流れが止まらないよう、埋めるときに ε を足しているのが要点。
   - **傾斜** — 標高の勾配から求める。
   - **近傍平均との高低差** — 半径およそ30mの平均標高との差。

3. **危険度ラスタにまとめる**（`app/hazards.py`）

   ```
   危険度 = (水が集まる度合い) × (水がはけない度合い)
   水が集まる度合い = 0.42×窪地 + 0.38×流域 + 0.20×近傍との高低差
   水がはけない度合い = 0.65 + 0.35×平坦さ
   ```

   傾斜を加算項ではなく倍率にしているのは、都心部はどこも平坦で、
   加算にすると全区間に同じ下駄が乗って「この道だけ危ない」という差が消えるため。
   流域面積も、絶対値ではなく対象地域の歩道上での分布（中央値〜97パーセンタイル）で
   正規化している。同じ理由で、固定しきい値だと値が一箇所に潰れてしまう。

4. **危険地点を抜き出す**（`app/hazards.py`）
   危険度の高いセルから順に、歩ける道から12m以内で、すでに採用した点から55m以上
   離れているものを採用する（貪欲な非最大値抑制）。建物の中や線路上の窪地は落ちる。
   判定理由の文面もここで組み立てる。

5. **地点名の一覧を作る**（`app/network.py` / `app/places.py`）
   OSMから駅・施設・名前つきビルを集める。チェーン店は目印にならないので落とす。
   引くときは種別ごとに探索半径を変え（駅300m・施設160m・ビル70m・道路45m）、
   半径で正規化した距離がいちばん小さいものを採る。300m先の駅より20m先のビルの
   ほうが説明として役に立つため。ただし駅が150m以内にあるときは駅を優先する。
   駅のそばなら、人はその駅名で場所を言うため。

6. **歩行グラフに危険度を付ける**（`app/routing.py`）
   OSMの道路のうち歩けるものだけを残してグラフにし、最大連結成分を取る。
   各辺について危険度ラスタを8m間隔でサンプリングし、平均と最大を辺に持たせる。

## ルート探索

同じダイクストラ法を、コスト関数だけ替えて2回まわす。

| ルート | コスト |
| --- | --- |
| 最短 | `距離` |
| 回避 | `距離 × (1 + 4.0 × 実効危険度)` |

実効危険度は、辺の危険度に雨量の倍率（弱雨0.55／中雨1.00／強雨1.45）を掛けたもの。
危険な区間を「実際より長い道」として扱うことで、遠回りしてでも避ける経路が選ばれる。

## ルートの危険度（％）の定義

画面に出る「危険度 68%」は、**そのルートを歩いて水たまりに出くわす推定確率**。

```
区間ごとの遭遇率 = min(1, 実効危険度 / 0.35) × 区間長 / 500m
危険度 = 1 - exp(-Σ 区間ごとの遭遇率)
```

同じ危険度の道でも長く歩けばそれだけ出くわしやすい、という形にしてある。
地形スコアの単純平均にしないのは、平均だと「ほとんど安全だが一箇所だけ深刻」な
ルートが薄まってしまうため。

## 構成

```
app/
├── config.py    デモ対象地域・雨量プロファイル・モデルの係数（調整はここだけ）
├── geo.py       緯度経度・タイル座標・距離の計算
├── terrain.py   標高タイルの取得と、窪地・流域・傾斜の算出
├── hazards.py   危険度ラスタの生成と、危険地点・判定理由の抽出
├── network.py   OSMからの歩行空間ネットワーク構築と、地点名の収集
├── places.py    座標から「東京駅」「〇〇ビル 付近」を決める
├── routing.py   ダイクストラ法によるルート探索と危険度の採点
├── models.py    APIのスキーマ（frontend/src/types.ts と対応）
├── service.py   リクエストごとの組み立て
└── main.py      FastAPIアプリ
scripts/build_data.py   生成物の作成
tests/test_api.py       APIの振る舞いの確認
data/cache/             取得した生データ（gitignore、取り直せる）
data/generated/         APIが読む生成物（コミット済み）
```

## 既知の割り切り

- 危険度は**地形だけ**から推定している。排水設備・舗装材・実際の冠水履歴は見ていない。
  UIに「※東京都の地形データに基づく推定です」と出しているのはそのため。
- 対象地域はデモ用に絞っている。範囲外の指定は400で弾く。
- 標高はDEM5A（地表面）なので、高架下・地下道など立体交差の扱いは正確ではない。
- 危険度の絶対値ではなく、**同じ地域の道どうしの相対比較**として読むのが正しい。
